Configuration, four ways

The same file each time: InterFAX Support's after-hours config, version 3. None of them reads the file back as sentences. Pick one and it gets ported into 24/7 › Configuration.

A · FormB · File firstC · Overview tilesD · Products table
A · FormEvery value as a control you can read at a glance

Times are pills, weekends are a segmented control showing the choice, keywords are chips, and the manager is a person row. Read only: changes still come by uploading a new version. Like Vercel or Linear project settings, and Copilot's Customization page on Mobbin.

B · File firstThe file is the page; what AiMY reads sits beside it

The way GitHub shows a workflow file: the file with line numbers on the left, a narrow panel on the right with the parsed values, the status and the versions. Closest to what the file actually is.

C · Overview tilesFour facts up top, the rules under them

The four things someone checks first (hours, who is called last, how long AiMY stands back, how long it watches after an answer) as tiles, then urgent and not urgent side by side as chips. Versions and templates below.

D · Products tableEvery product's file in one table, details in a side panel

The page opens on the client: a row per product with its hours, manager, version and status, so a missing file stands out. Choosing a row fills the panel on the right; no row opens in place. Like Braintrust's and Front's rule tables on Mobbin.
